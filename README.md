# Kotib

Один Telegram-бот на личном аккаунте Javohir'а через Telegram Business. Секретарь: если клиент написал,
а ответа нет N минут, ИИ отвечает как «ассистент Джавохира», уточняет задачу и присылает карточку лида.
Шпион: хранит личные чаты и сообщает, что собеседник удалил или изменил. Контракт: [SPEC.md](SPEC.md).

## Подключение

1. В @BotFather у бота включить Secretary Mode (в Bot API это по-прежнему business_*).
2. В Telegram: Настройки → Telegram Business → Чат-боты → выбрать бота, доступ к личным чатам,
   включить право отвечать (управление сообщениями).
3. Владелец один: `OWNER_ID` в `.env` или первый, кто подключит бота. Чужие подключения бот игнорирует
   и ничего из них не хранит.

## Локально

```bash
python3.12 -m venv .venv
.venv/bin/pip install -r requirements-dev.txt
cp .env.example .env   # BOT_TOKEN, OWNER_ID, ключ ИИ; DATA_DIR=data
.venv/bin/python -m bot.main
```

На один токен держать один поллер: если бот уже работает на сервере, локальный запуск ему помешает.
Без ключа ИИ бот работает: шпион полностью, секретарь выключен с понятным статусом в меню.

## Тесты

```bash
.venv/bin/python -m pytest -q
```

В сеть не ходят: настоящий Dispatcher, бот с мок-сессией (`tests/harness.py`), фейковый ИИ и часы.
Реальный `.env` тесты не читают.

## Деплой

```bash
./deploy.sh
```

Только закоммиченное: rsync на `root@62.83.87.250:/opt/tg-secretary/` (без `.env`, `data`, `.venv`, тестов),
`docker compose up -d --build`, хвост логов. `.env` на сервере свой, `chmod 600`. Контейнер `tg-secretary`,
uid 10001, портов нет, long polling.

## Данные

`DATA_DIR` (`/app/data` в контейнере): `kotib.db` (SQLite, WAL), `media/` (копии медиа, 30 дней),
`kb/knowledge.md` и `kb/style.md` (рабочие копии, бэкапы в `kb/backup/`). Сообщения хранятся 60 дней,
чистка каждый день в 04:00 по Ташкенту. Одноразовые и защищённые от пересылки сообщения не хранятся.
В логах только id и типы, без текстов.

## База знаний

`kb/` в репозитории копируется в образ как дефолт. Заменить: прислать боту файл `knowledge.md` или `style.md`
документом. HTML-комментарии `<!-- ... -->` в файлах это внутренние заметки: в промпт ИИ не попадают.

## Команды владельца

`/start` меню (режим, задержка, шпион, расход ИИ), `/chats` режим ИИ по чатам, `/leads` открытые лиды,
`/test` песочница секретаря, `/stop` выход, `/pause 2h`, `/resume`, `/hours 20:00-09:00` нерабочие часы
для режима «вне работы».
